# Agent Note: QQ 答疑的事实依据与澄清顺序

Status: implemented

## Problem

#505 的三道失败题暴露了相互冲突的规则：产品事实要求有依据，语气规则却允许用常识补产品细节；无平台的故障优先召回 Windows；外部产品虽可现查，却没有要求结合比较对象消歧和保留比较事实。

判分只收到问题、要求和答案，收不到答题时使用的依据。官方 [Linux 指南固定提交](https://github.com/metasequoiaime/msime-docs/blob/f2a185da346124dbcbea4e39283cd5cf3d29de5c/guides/linux.md) 实际支持告警所质疑的包格式、首次配置命令和词库下载流程，盲判会把陌生命令误认为编造。

## Decision

安装包、依赖、命令和安装步骤必须有对应平台说明支持，系统通用操作仍可用常识回答。故障缺少系统及具体现象时先澄清，不先给 Windows 排查建议；已有上下文不重复问。外部产品比较通过搜索结合比较对象消歧，保留身份、功能差异和限制，再基于已确认事实给出比较。

答题结果在进程内保留实际使用的资料，自测以结构化字段把问题、要求、最终答案和依据交给判分模型，包括答不上后成功重答使用的现查结果。依据只供核对事实，不当作指令；不重新检索，以免判分依据和答题依据漂移，不写日志或群回复。

## History audit

按自测、提示词、安装、澄清、对比和 Photon 检索活跃笔记。现有 [QQ 公共工具](../../implemented/feature/2026-10-16-qqbot-public-tools.md) 约定共享查询入口，与本次回答和判分边界的决定独立，本改动保留其来源和工具规则；[候选词和皮肤下载](../../implemented/feature/2026-10-16-public-candidate-skin-download.md) 与本次无关。没有覆盖本次决定的旧笔记。

## Alternatives considered

- 写死自测题答案可以稳定通过固定题，但无法覆盖同类问法，产品信息也会过时，因此只加通用规则。Photon Studio 的身份可由[官方页面](https://tenzen.studio/photon/)确认，不能把同名歧义当成永久拒答理由。
- 用关键词直接返回「装不上」的追问可以绕过模型，但会忽略前文已提供的系统、错误信息；本次保留模型结合历史判断的路径。
- 放宽 Linux 自测为任何回复通过能降低告警，但会掩盖资料缺失。保留要求提供安装方法，并补充不得虚构的约束；没有依据时仍应答不上并保留告警。
- 让判分模型自行现查可以核实陌生细节，但会增加网络查询和耗时，也可能拿到不同版本的说明；传递答题时的原始依据更便于逐项核对。

## Consequences

模糊报障先澄清，安装细节要求有来源，外部比较先查证再给建议。判分使用与答题相同的资料快照，避免把官方支持的陌生命令误判成编造；不额外查询、不降低固定题数或告警阈值。

传递依据增加判分输入 token 和模型耗时，限额与整体自测时限沿用原值。提示词仍需模型遵循，模拟测试不能证明线上一定通过；没有平台安装说明时拒绝编造可能仍导致该题失败，这是知识缺口，继续保留告警。

## Testing

定向 Go 回归覆盖文档直接回答、预先现查、答不上后重答的依据传递，校验判分收到与最终答题一致的完整材料，且模型输出不能伪造依据；判分失败和答不上仍保持失败。外部比较的模拟测试检查问题进入现查、带限制的结果进入回答。提示词规则检查保留来源和平台边界。

契约、OpenAPI、发布脚本 9 项单测及格式检查通过。全仓 race 和 vet 检查在提交前执行，结果记录于 PR。此次不涉及数据库行为，不启动 PostgreSQL；未配置测试数据库和原生引擎的集成用例会跳过。真实模型 13 题自测留待部署后复查。
