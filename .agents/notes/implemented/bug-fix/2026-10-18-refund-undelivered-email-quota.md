# Agent Note: 退回未投递邮件额度

Status: implemented

## Problem

全站发信额度在 SMTP 连接、认证、`MAIL FROM` 或 `RCPT TO` 阶段失败时也会被占用。此时邮件尚未进入 `DATA`，不会产生可交付的消息；服务故障或收件服务器临时拒收时，重试会更快耗尽每日额度。

## Decision

邮件投递错误带有是否已经进入 `DATA` 阶段的内部状态。连接、认证、`MAIL FROM`、`RCPT TO` 和 `DATA` 命令本身失败都标记为未投递，调用方退回本次 `delivery-global` 预留；正文写入或 `DATA` 结束确认之后的错误保持扣额，因为消息可能已经被供应商接受。`RCPT` 阶段 5xx 仍沿用永久地址抑制；其他错误不写入抑制表。

错误状态只在服务内部传播，HTTP 响应仍是通用的 `delivery_failed`，不向客户端暴露 SMTP 响应正文。

## Alternatives considered

- 所有发送失败都退回额度：`DATA` 后的连接中断可能发生在供应商已经接收消息之后，退回会允许重复投递同一封验证码。
- 所有发送失败都保留额度：不会重复投递，但连接或认证故障会把免费额度浪费在没有生成邮件的请求上。
- 只按 SMTP 状态码判断：同一个状态码在不同阶段含义不同，不能区分“未交给供应商”和“已交给供应商但确认失败”。

## Testing

- 单元测试验证 `RCPT` 5xx 的永久分类，以及 `DATA` 前后错误的退款边界。
- 既有 SMTP TLS、STARTTLS、验证码和下载链接测试继续覆盖实际发送路径。

## Consequences

供应商不可用或收件服务器在收件人确认前拒绝时，额度可以用于后续真正的投递；进入 `DATA` 后仍保守扣额，避免网络不确定性造成验证码重复发送。该判断只覆盖同步 SMTP 错误，异步退信仍需独立反馈入口。
