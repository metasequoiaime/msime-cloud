# Agent Note: 官网累计下载包含国内镜像

Status: implemented

## Problem

官网只展示 GitHub 快照，虽然国内镜像点击已保存在后端，却被排除在累计下载外。这违背维护者明确要求的总下载口径。

## Decision

公开只读接口 `/v1/site/download-stats` 汇总所有历史 `kind=download` 且 `channel=cn-mirror` 的事件，返回合计、规范平台分项和生成时间。合计等于全部分项之和，未知平台也计入。事件 ID 的既有唯一键负责重试去重，不加日期窗口，不使用后台最近七天差分。

官网复用其已有的完整 GitHub 安装包快照，与本接口的镜像累计值相加，向访客统一展示累计下载。后端不重新实现 GitHub 文件分类，避免两套规则产生不同总数。只公开聚合值，不公开事件明细和任何账号或设备资料。接口沿用公开信息流每地址每分钟 1200 次额度，响应缓存 60 秒，无新表和新凭据。

## Alternatives considered

直接使用后台 `/api/downloads/summary` 可以复用近期报表，但它只统计最近七天且需要管理员权限，不能提供全历史公开总数。重新汇总后端 GitHub 资产快照可以把所有来源集中到单一接口，但其每日抓取与官网完整分页快照不同，复制包格式分类也会形成两份权威，因此仅提供缺失的镜像补充值。

## Consequences

累计下载包含国内镜像历史数据，官网无需管理员令牌。镜像以已接受点击计数，不等于完成下载或安装人数；此前未上报的下载无法补回。平台为 `windows-rust` 的新事件可独立归入 Rust 版；旧 Windows 事件缺少产品仓库信息，不能推断过去 Rust 镜像的精确分项。

PostgreSQL 测试覆盖 400 天前的下载、别名、未知平台、无关事件排除、合计守恒、零数据、匿名读取、限流分组、禁用服务和数据库失败。公开接口契约和 API 行为清单同步更新。

## Related notes audit

检索活跃笔记的下载与镜像关键词：候选窗皮肤匿名下载记录描述社区资源权限，与安装包累计统计无关；邮件下载链接记录描述投递额度，也无关，均保留。
