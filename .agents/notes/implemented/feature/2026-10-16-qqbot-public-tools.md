# Agent Note: QQ Bot、MCP 与 CLI 共用公共查询工具

Status: implemented

## Problem

QQ Bot 的现查只支持 GitHub 和网络搜索，无法确认发布词库里的候选、注音、释义，也不能查询本站公共社区目录。CLI 已能直接调用 HTTP API，但没有与 Bot 共用的工具目录或通用 MCP 入口；把本机输入法的 MCP 接进云端会混入个人词库和本机文件。

## Decision

在 `internal/publictools` 维护受限的只读工具目录和请求构造：`lookup_dictionary` 查询发布词库及固定输入数据，`browse_input_catalog` 浏览表情、颜文字和符号，`query_public_data` 查询公共公告、社区统计、词包、插件和皮肤。工具参数不能携带原始 URL、私人路径、凭据、shell 命令或资源目录。

字典工具先做共享 schema 校验，再按最终 `operation` 构造 HTTP 请求。仅候选、简拼、表情、颜文字、分词和注音保留 `scheme/profile`，仅释义与假名转换保留 `direction`，仅辅助码保留 `schema`，仅日期查询保留 `time/timezone`；`text/limit` 是公共字段。模型可能填满共享 schema 的可选参数，工具层不能把其他操作的默认值透传给严格 HTTP 接口。未知字段、错误类型、枚举和范围仍在筛选前拒绝；当前操作自己的参数仍由原接口校验，不能把错误方向、日期或码表改成默认值。

辅助码查询 `helpcode` 使用 `schema` 选表。显式 `schema` 优先；未给 `schema` 时，只把同名的 `profile=xiaohe/ziranma` 兼容为辅助码表，其他双拼方案没有可靠映射，拒绝而不默默查默认表。两个字段均未提供时保留接口的蓝天默认表。按操作筛选和该兼容只作用于共用工具层，直接 HTTP 调用仍严格拒绝无关参数，候选和双拼查询保留原语义。

QQ Bot 现查直接调用本进程既有 HTTP 处理器，保留原有五次调用预算、时限和匿名社区访问规则。CLI 的 `tools` / `tool` 和 `mcp`（stdio）使用同一目录，通过既有 HTTP API 查询部署；仅词库和输入目录查询使用显式的 `MSIME_CLOUD_TOKEN`，公共社区查询不附加登录会话。客户端拒绝重定向，限制响应大小，错误不包含上游正文。

回答模型的内置能力说明也从同一个 `Definitions()` 目录生成工具名和说明，避免只有现查模型知道工具已接入、回答模型却照旧否认。只问能力不触发查询，实际要求候选、注音或公共目录时仍走现查。帮助文字和 QQ 指令面板提供 `/mcp` 入口，固定回复查词、注音、释义、辅助码和公共目录的自然语言示例。该命令沿用免费命令限流，不调用模型，个人、群或管理员问答额度用完时仍可查看；面板配置随代码提交，上线后按既有脚本同步。问 MCP/CLI 时说明它们与群内工具共用能力，群友无需另外连接，但机器人不能连接任意外部 MCP 或运行任意命令。是否查到结果以实际工具返回为准。

## History audit

检查了云端固定提交 `631418a51c0c0f3f774458d29e26f1d35a651f7a` 的文档和笔记目录，没有同一决定的笔记。`docs/diagnostics.md` 的快照 MCP 属于用户主动上传的一份私有诊断，不复用该鉴权入口；公共查询 MCP 使用 CLI stdio，职责不同。

## Alternatives considered

- 让 Bot 启动 CLI 或连接用户的本机 MCP：能快速复用现有输入法工具，但云端没有用户宿主，且会把 shell、个人词库和公共查询混在一起。共享 Go 工具层保留相同能力，不引入额外子进程或私人状态。
- 给模型任意 HTTP 路径：接口覆盖面最大，但管理后台、账号私有内容和有副作用的下载接口都可被误调用。固定工具和请求白名单更适合群聊。
- 只在现查提示词里声明工具可以减少普通答疑上下文，但能力问题不一定触发现查，回答模型可能只按旧功能清单拒答；回答模型同步接收共享目录，增加少量上下文来保持能力认知一致。
- 放宽 HTTP 接口对无关选项的校验，能让所有调用方免受多余参数影响，但会改变客户端接口的错误语义；公共工具层知道操作和字段用途，在这里归一化即可。仅修改模型提示词改动更小，却不能保证它不再附带双拼默认值，因此提示说明与请求归一化一起生效。
- 只移除辅助码查询中的 `scheme/profile` 能修复最初复现，但生产同款模型仍会填入 `direction/time/timezone`，实际调用继续返回 400。改为所有字典操作统一筛选所属参数，避免逐个字段和接口打补丁；保留单个工具与既有 MCP/CLI 调用格式，代价是字段归属需要随 HTTP 契约一起维护。

## Consequences

三个入口共用 schema、参数校验和查询路径；新增公共能力只需在同一目录登记。Bot 不启动 shell 或 CLI 子进程，MCP 客户端通过 CLI stdio 使用同一能力，不增加服务端 HTTP 入口。

社区数据保持匿名可见性，输入查询仅使用显式环境令牌；因此 CLI 保存的个人会话不能直接用于新工具。Bot 在进程内访问底层 mux，仅可执行工具层构造的固定路径；QQ 事件鉴权、消息限流与五次工具预算仍在外层。所有 Bot 社区请求共享一个固定内部地址的数据库限流桶，繁忙群之间会竞争公共额度。词库或数据库未配置时明确失败；本地工具的 HTTP 传输不跟随重定向，响应最多 1 MiB。

公共数据来自用户投稿，作为资料而非指令交给模型。词库和社区不可用时明确失败，不能把查询失败当成没有词条或作品。仅列出候选不能证明任意词语不存在于整份词库，Bot 必须说明查询方式和限制。

## Testing

- 共用查询层覆盖未知工具、参数类型与范围、路径注入、私人筛选参数、取消、响应上限和重定向；HTTP 测试确认公共请求不携带令牌或 Cookie。
- CLI 测试覆盖命令分发、stdin 参数、已保存会话隔离与真正的 MCP stdio 握手和调用；MCP 测试覆盖工具发现、调用与参数错误。
- QQ 测试通过模型工具调用往返验证工具目录、结果来源与五次预算；独立 PostgreSQL 验证公开皮肤可读而私人皮肤不能被列出或读取。
- 发布词库回归通过 QQ 共用工具入口覆盖五种辅助码表、小鹤查询附带候选默认值以及只给小鹤 profile 的兼容请求。CI 的原生引擎触发范围包含 `internal/publictools/`、CLI 工具入口与 QQ 公共工具及测试，避免这些入口改动时跳过真实引擎验证。
- 全部 16 种字典操作通过真实 HTTP 处理器和锁定引擎，比较仅填写所属参数与附带其他操作默认值的结果；原有 HTTP 严格参数校验保持不变。辅助码用合成字符验证，回归在修复前复现 `public_api_status_400`，不向真实群发消息。
- 使用生产同款模型和原工具定义查询合成字符，实际生成的非空 `direction/timezone` 在旧 CLI 上失败，同一组参数在修复版上返回正确小鹤码。真正 MCP stdio 握手后，对部署 API 发送含其他操作默认值的辅助码调用，旧版返回 400，修复版成功；另一次真实模型查询把成功的工具结果交回模型后，摘要包含正确辅助码。此类探针不经过 QQ 消息收发，不能代替上线后的群内验收。
- 修复版 CLI 与真正的 MCP stdio 握手后连接部署 API，分别用合成字符验证附带候选选项、仅提供小鹤 profile 的两种请求；两者都返回小鹤表结果。此验证不向真实 QQ 群发消息，群内自然语言模型是否正确选择工具仍需部署后观察。
- 能力介绍回归检查实际回答请求包含共享目录的每个工具及说明，且单纯问能力不触发现查；帮助入口包含 `/mcp`，命令在问答额度耗尽时仍返回查词和公共数据示例，免费额度耗尽时照常限流，且不调用模型或创建 issue。模型措辞仍需上线后观察，模拟测试不替代真实群聊验收。
- 契约、OpenAPI、发布脚本单测与 Go vet 已通过。真实引擎及发布词库测试使用锁定的 `third_party/msime` 和校验资源通过；相关入口的 race 测试通过。全仓 `go test -race ./...` 首轮在未改动的 account/server 数据库故障测试中因 PostgreSQL 等待超过默认 10 分钟时限而超时；相关入口的测试没有断言失败。全仓数据库检查改在与临时 PostgreSQL 相同的容器网络内重跑，最终结果另行记录。
