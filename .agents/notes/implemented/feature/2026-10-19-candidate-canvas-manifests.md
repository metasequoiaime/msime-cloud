# Agent Note: 云端候选皮肤清单与跨平台客户端对齐

Status: implemented

## Problem

跨平台客户端已接受 msime-windows 的 `canvas`、`wechat_scroll`、几何与九宫格清单，但服务端的 `ParseStored` 和种子脚本仍使用旧方言。社区上传即使只含合法 PNG 也被基底或引用集合拒绝，数据库目录也无法提供这类皮肤。

## Decision

以 msime 固定提交 `207a8c590bc1a3c06ff26348953d3495101ecc8d` 的共享扫描器为来源，同步共享用例表，移植新增字段的范围、类型、路径和版本规则。Go 与离线 SQL 种子脚本按同一份合成用例验证。清单原始字节继续保留；公开目录 JSON 的现有形状不增加绘制字段，社区引用校验使用仅在服务端保存的图片集合。

保留 ID 加入 `canvas`、`wechat_scroll`；数据库资源扩展名加入 `.apng`（媒体类型 `image/png`），配套迁移与 Ready 检查。旧行不回头校验，新写入受约束。只准备代码与 PR，不执行生产迁移或发布。

## Alternatives considered

- 只放行两个 base：代码最少，但无效几何会绕过客户端相同的校验，且九宫格和挂件仍被当作未引用资源拒绝，因此不用。
- 在目录 JSON 加入全部新绘制字段：客户端可不下载清单便开始绘制，但扩大了既有未协商响应格式；当前客户端仍读取原始清单，因此使用内部引用集合，保留公开形状。

## Testing

Go 和种子脚本共用固定来源的 240 条方言用例及新增的 123 条合成边界用例。PNG 画布包经过完整上传校验；遗漏资源和非生效引用拒绝。HTTP 回归覆盖发布、落库、下载后的重新解析；数据库回归覆盖旧约束升级、重复迁移和越界路径拒绝。全仓 race、vet、后台构建、契约与发布脚本检查通过；数据库验收结果随本批提交记录。

## Consequences

本次先恢复清单与资源引用契约。社区图片数量、GIF/WebP 编解码和客户端上传拦截仍需后续配套，不能以本次测试宣称所有上游动画皮肤已能往返社区。现有 APNG 仅支持 `.png` 后缀，扩展名兼容需在上传层一起处理。


本次检索活跃笔记中的 `canvas`、清单和候选皮肤机制，已有 QQ 公共工具与邮件指标笔记只涉及读取与统计，没有可承接本次清单契约的决定。新的范围校验提高与共享扫描器的一致性，代价是 Go 与种子脚本仍各自实现校验，后续变化需继续以共享用例同步。
