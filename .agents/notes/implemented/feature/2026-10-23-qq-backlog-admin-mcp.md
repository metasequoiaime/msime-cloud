# Agent Note: 通过管理员 MCP 管理 QQ 草稿与读取文档缺口

Status: implemented

## Problem

QQ 提醒中的 D 草稿和 F 文档候选保存在 PostgreSQL，现有 MCP 只有公共词库与社区数据，管理员无法在助手里分页查看积压及完整详情。

## Decision

显式启用 `msime-cloud mcp --admin`，提供四个读取工具和三个草稿管理工具，只访问管理员主机上的固定路径；使用现有管理员登录或 `MSIME_ADMIN_TOKEN`，每次请求检查会话有效期。接口要求 `triage_issues` 权限，返回白名单字段，不返回群及成员身份摘要。公共工具目录和 QQ 模型不包含管理员工具。

列表按创建时间及编号升序，默认 20 条、最多 100 条，返回总数与分页信息；沿用 30 天有效期和认领超时语义，详情不认领、不提交、不忽略。CLI 同时支持 `tools --admin` 和 `tool --admin`。

`update_qq_draft` 通过显式字段修改原话或结构化报告，不再调用模型；要求携带详情中的 `updated_at`，在行锁内验证时间与内容快照。编辑和 `close_qq_draft` 的忽略操作都与审计同事务提交，关闭不删除记录、不关闭 GitHub issue。只有未处理或认领超时的草稿能修改或关闭。

`submit_qq_draft` 在认领时读取最新快照，复用 QQ 的 Windows 产品分流、跨副本仓库锁、查重、建 issue 或补充评论。明确的 GitHub 拒绝和写入前失败释放租约；写入结果不确定保留租约，沿用五分钟超时恢复规则，禁止工具自动重试。GitHub 接收成功后，即使请求取消，也独立限时登记 issue 和操作者；登记或审计失败用响应中的 `recorded` / `audited` 告知，不能再次提交。提交服务端上限两分钟，工具上限 130 秒，均短于认领期限。写工具声明可修改数据，只有关闭标注幂等。

## Alternatives considered

- 直接加入公共工具目录能复用所有入口，但群聊模型与公共客户端会发现私有工作流，且公共传输刻意不读取管理员会话。显式管理员模式保持原有隔离，见[公共工具决定](../../implemented/feature/2026-10-16-qqbot-public-tools.md)。
- 直接查询 GitHub 无需新接口，但 D/F 尚未提交，数据库才是这些计数和正文的来源。
- 复用聊天命令的自然语言补充可以少一份编辑接口，但会让模型重新整理不可预期地修改其他字段；管理工具采用结构化补丁，保留未提供的字段，要求先读后改。

## Testing

测试覆盖真正的 MCP stdio 握手、七个工具的发现与调用、环境令牌与已保存会话、过期会话拒绝、公共目录隔离、参数边界、响应上限和重定向。独立 PostgreSQL 回归用合成数据验证 25 条积压跨页和空页总数、有效期、完成与忽略状态、活跃及超时认领、完整详情、身份字段隔离和读取无副作用；数据库失败不会伪装成空列表。管理测试验证并发编辑只有一份成功、旧版本冲突、审计失败回滚、重复关闭、提交和查重评论、Windows 缺版本及确认未知、GitHub 拒绝释放和未知结果保留认领。

## Consequences

管理员可以在助手里读完全部积压并按编号编辑、提交或关闭草稿，不再受 QQ 单次十条列表限制；权限和数据生命周期复用现有后台与 PostgreSQL。管理员查询会返回反馈正文，助手必须把它当资料而非指令；提交将其公开到 GitHub，需要明确的提交意图。列表和详情不是跨请求快照，并发处理可能使分页移动。结果不确定后人工需要核对 GitHub，五分钟后的恢复仍依赖现有查重，不提供跨 GitHub 与数据库的恰好一次保证。服务端和 CLI 均需升级，新 CLI 访问旧服务端明确返回错误。F 文档候选仍只读。
