# Agent Note: 通过管理员 MCP 读取 QQ 草稿与文档缺口

Status: implemented

## Problem

QQ 提醒中的 D 草稿和 F 文档候选保存在 PostgreSQL，现有 MCP 只有公共词库与社区数据，管理员无法在助手里分页查看积压及完整详情。

## Decision

显式启用 `msime-cloud mcp --admin`，提供四个只读工具，查询管理员主机上的固定 GET 路径；使用现有管理员登录或 `MSIME_ADMIN_TOKEN`，每次请求检查会话有效期。接口要求 `triage_issues` 权限，返回白名单字段，不返回群及成员身份摘要。公共工具目录和 QQ 模型不包含管理员工具。

列表按创建时间及编号升序，默认 20 条、最多 100 条，返回总数与分页信息；沿用 30 天有效期和认领超时语义，详情不认领、不提交、不忽略。CLI 同时支持 `tools --admin` 和 `tool --admin`。

## Alternatives considered

- 直接加入公共工具目录能复用所有入口，但群聊模型与公共客户端会发现私有工作流，且公共传输刻意不读取管理员会话。显式管理员模式保持原有隔离，见[公共工具决定](../../implemented/feature/2026-10-16-qqbot-public-tools.md)。
- 直接查询 GitHub 无需新接口，但 D/F 尚未提交，数据库才是这些计数和正文的来源。

## Testing

测试覆盖真正的 MCP stdio 握手、四个工具的发现与调用、环境令牌与已保存会话、过期会话拒绝、公共目录隔离、参数边界、响应上限和重定向。独立 PostgreSQL 回归用合成数据验证 25 条积压跨页和空页总数、有效期、完成与忽略状态、活跃及超时认领、完整详情、身份字段隔离和读取无副作用；数据库失败不会伪装成空列表。

## Consequences

管理员可以在助手里读完全部积压并按编号查看详情，不再受 QQ 单次十条列表限制；权限和数据生命周期复用现有后台与 PostgreSQL。管理员查询会返回反馈正文，助手必须把它当资料而非指令。列表和详情不是跨请求快照，并发处理可能使分页移动。服务端和 CLI 均需升级，新 CLI 访问旧服务端明确返回错误。
