# Windows Server 公共 API 抽取清单

目标：把 Windows Server 中不依赖本机输入上下文的服务能力全部提供为公共后端 API。公共表示跨平台共用，不表示匿名开放用户数据。生产 `docs_enabled` 继续为 false。

核对来源：Windows `server/src/settings/settings_app.cpp`、`dictionary_manager.cpp`、`clipboard/clipboard_history.*`、`skin/candidate_skin_catalog.*`、`english/english_ime.cpp`、`emoji/emoji_ime.cpp`、`kaomoji/kaomoji_ime.cpp`、`emoji-panel/EmojiPanel.cpp`、`conversion/chinese_converter.cpp`、`ipc/event_listener.cpp` 和 Engine contracts。Windows 工作树有用户未提交修改，只读核对，不覆盖。

以下留在客户端，不创建远程操作入口：TSF/COM/Named Pipe 协商，按键吃键与焦点、composition 代次、候选上屏和窗口控制，DPI、UIAccess、WebView2、托盘、打开本机目录/外部程序、麦克风采集/播放/静音、系统剪贴板监听、Windows 手写 COM 识别、本机文件切换与安装升级。这些操作依赖本机权限或活动输入会话；其中可复用的数据和纯查询仍包含在上表，不以“本机功能”为由省略。

验收：逐项落实接口、严格参数限制、租户隔离及并发/失败测试、OpenAPI（仅开发显式开启）、生产迁移及真实数据验证。Windows 客户端自动上传私人输入或剪贴板不属于接口新增，不会静默开启；客户端接入需显式用户操作。

容量验证使用 `MSIME_TEST_LARGE_RESTORE=1` 显式开启 `TestSnapshotRestoreAtEntryLimit`，避免日常单元测试重复生成十万词条。原生快照载入按固定 Engine 版本的日志表结构批量传输最终状态；原生 Engine 继续负责词库分区、回放、调频和查询。日志结构随 Engine 升级时，需同时运行候选所有权、删除、固定位置、计数恢复及容量测试。

Linux 容器验收：完整资源已打包到只读镜像，非 root UID 65532 可读取；`scripts/smoke_container.py --native` 在 2 CPU / 2 GiB 限制下通过拼音、注音、OpenCC、罗马字和四路并发日语查询，文档入口为 404。此检查已在原生 CI 通过；生产新增用户数据表已迁移，运行账号只有所需 DML 和数据库 TEMP 权限，没有 public schema CREATE 权限。公网容量验证结果见下文。

## 0.3.0 发布验收（2026-09-08）

[后端 PR #5](https://github.com/metasequoiaime/MSIME-Backend/pull/5) 已合并，[0.3.0 正式版本](https://github.com/metasequoiaime/MSIME-Backend/releases/tag/backend-v0.3.0) 已发布并部署到 `https://api.msime.app`。发布源码为 `6eeef76`，镜像同时包含 Linux AMD64 和 ARM64，清单摘要为 `sha256:aad146c5d52ec7e99fd5cb95c9a4a77e5f14d3d68213f56cb81c652eb3e7d3c9`。生产实际运行摘要与发布镜像一致。

- [合并前 CI](https://github.com/metasequoiaime/MSIME-Backend/actions/runs/34192911308) 全部通过：三平台 Go race/vet/build、真实 PostgreSQL、发布词库、资源摘要与只读非 root 镜像。固定 Engine 版本及资源摘要见 `native/resources.lock.json` 和子模块提交。
- 公网 52 项公共接口检查通过，包含原有合作接口、各输入方案、日语模型、目录、皮肤资源及鉴权拒绝场景。实时语音另外使用约 3.9 秒合成录音验证了中间结果和最终文本。
- 公网用户数据验收使用临时会话和合成数据：70 次 HTTP 状态检查以及设置版本冲突、显式剪贴板同意/去重、四类词库编辑和隔离、跨方案固定位置、普通候选调频、管理编辑、Windows 格式往返、注音导入及快照恢复断言通过。候选删除另行验证删除后查询不再返回该条目。
- 固定位置候选禁止再次调频，沿用 Engine 规则并返回 400；普通候选调频后实际排名符合预期。设备令牌不能访问用户数据。第三方登录渠道是否启用由 `/v1/auth/providers` 和独立部署配置决定，临时会话验收不代表已完成各渠道的真实登录。
- 公网容量样本包含 100,000 条英文词条及对应覆盖记录，上传 35,555,766 字节；恢复约 32.4 秒、个人候选查询约 5.5 秒、完整导出约 11.9 秒。核对数据库词条/覆盖计数各为 100,000、另一用户候选隔离，以及导出的 200,001 条数据记录和 SHA-256。时间包含公网传输，仅代表该样本与当时部署环境。
- 生产使用 2 CPU / 2 GiB 上限、2 GiB 临时目录及只读根文件系统。新 Pod 启动时曾短暂连接数据库失败，重试后正常；容量测试期间没有新增重启。所有临时账号、关联数据和诊断资源已清理。
- `/healthz` 返回 200，Swagger/OpenAPI 在匿名、设备令牌和用户会话下均保持 404。公开接口契约可从仓库中的 OpenAPI 文件读取；开发环境需显式启用文档。
